# Review-view state stays in the view; no ReviewSession extraction

`plugin/src/view.ts` holds selection, loading, autosave, accept/reject/undo and `checked-until` state, and is only testable inside Obsidian. Issue #54 proposed extracting that state into a `ReviewSession` module so it could be tested under `node --test`. We decided against it (2026-10-02). Its two user-facing motivations are already covered without it. Before a page's first edit the produced page block is kept as a stash (#140). Marking a page as wrong turns it into a page case through `plugin/src/page-cases.ts`, which already runs headless. What remains is testability of selection and load ordering. Those bugs have not recurred since the view stabilised in August 2026: of 11 fix commits on `view.ts`, 8 date from 16–17 August. A large refactor would not change a single page the user reviews. Revisit only if that state starts breaking again, with the failing scenario named first.

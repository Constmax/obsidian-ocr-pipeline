# OCR Preview — Not Wiki Content

Raw conversions of `raw/` PDFs to Markdown, generated by
`pdf2md` (`bin/pdf2md` in the pipeline repo). Purpose: **Inspection in Obsidian**, nothing more.

This folder does **not** follow the wiki conventions from `AGENTS.md`:

- No mandatory frontmatter schema (`titel`, `typ`, `rechtsgebiet`, …)
- No `[[wikilinks]]` to wiki pages
- Not indexed by `lint_wiki.py` (and **must not** be)
- Not indexed by `semantic_search.py` (which only reads `wiki/*.md`)

Anyone wishing to turn these into wiki pages should use `/jura-ingest` — do not move these files manually.

## Marker Grammar

Pages are separated by `%% p. {nr} | {source} | {layout} %%` comment lines.
The grammar and the rules for producers and readers are specified once, in
[preview-format.md](preview-format.md#2-page-markers). No consumer exists
other than the review view: neither `lint_wiki.py` nor `semantic_search.py`
touch this folder.

## The Three-Folder Model

Files move between three flat sibling folders — the folder location **is** the status:

```
_ocr-preview/              open (awaiting review)
_ocr-preview/.cache/       resumable per-page OCR results (generated, Issue #11)
_ocr-preview/_accepted/    accepted
_ocr-preview/_rejected/    rejected (nothing is ever deleted)
```

These are the plugin's default folder names; all three are settings. A vault
set up before the rename keeps its `_ocr-vorschau/` folders
([installation.md](installation.md)).

`review-status.json` in the same folder is merely an **annotation cache**
(`notiz`, `geprüft-bis`, manual PDF mapping) and can be safely deleted at any time. Details on reconciliation rules: [review-view.md](review-view.md).

`_ocr-preview/.cache/` is likewise generated state, not review content: it is
safe to delete, is ignored by Git, and has no bearing on the three-folder model
above. See [scripts-detail.md](scripts-detail.md#page-cache-and---refresh-cache-stage-2)
for its lifecycle and the `--refresh-cache` flag.

`_ocr-preview/assets/` remains where it is: All three folders share the diagram images (`![[…png]]`); they are **not** moved alongside.

## Frontmatter Fields

| Field | Meaning |
|---|---|
| `seiten-textlayer` | Lossless from PDF textlayer, exact bold styling |
| `seiten-ocr` | Read via PaddleOCR-VL — **word errors possible** |
| `seiten-diagramm` | Embedded as page image, text inside collapsed callout |
| `woerter-verdaechtig` | Matches from dictionary check, **still in text** |
| `woerter-korrigiert` | Matches replaced during run (only with `--dictionary-correct`) |

When `seiten-ocr > 0`, the `Quelle:` link to the original serves as safety net: OCR word errors cannot be mechanically corrected in all cases.

`woerter-verdaechtig` is a work list, not a defect judgment: words remain unchanged in the file, logged during the run with page number and suggestion (`⌕` line), fully viewable with `--dictionary-report <file>.json`. If both are missing, no dictionary was installed — the run will report this.

## Re-generating

```
pdf2md "raw/ZR/…/file.pdf" --out _ocr-preview
```

If a tile derails (repetition loop, exploding count, abort), it is re-calculated with finer slicing. Every such occurrence is listed as a `⚠` line in the run log — even when repair was *not* successful. If you only want detection without re-calculation:

```
pdf2md "raw/…/file.pdf" --out _ocr-preview --retries 0
```

Dictionary checking: Enabled by default in reporting mode. Replace clear-cut cases with `--dictionary-correct`, disable with `--no-dictionary`. Sources and limits: [scripts-detail.md](scripts-detail.md).

Benchmark metrics and error categories: [../bench/ERGEBNIS.md](../bench/ERGEBNIS.md).

# OCR Preview — Not Wiki Content

Raw conversions of `raw/` PDFs to Markdown, generated by
`.ocr-bench/pdf2md.py`. Purpose: **Inspection in Obsidian**, nothing more.

This folder does **not** follow the wiki conventions from `AGENTS.md`:

- No mandatory frontmatter schema (`titel`, `typ`, `rechtsgebiet`, …)
- No `[[wikilinks]]` to wiki pages
- Not indexed by `lint_wiki.py` (and **must not** be)
- Not indexed by `semantic_search.py` (which only reads `wiki/*.md`)

Anyone wishing to turn these into wiki pages should use `/jura-ingest` — do not move these files manually.

## Marker Grammar (Contract)

`pdf2md.py` separates pages using a comment line natively understood by Obsidian:

```
%% p. {nr} | {source} | {layout} %%
```

| Part | Meaning | Allowed Values |
|---|---|---|
| `nr` | Page number in PDF, 1-based | Integer |
| `source` | Provenance of the text | `textlayer` \| `ocr` \| `diagramm` |
| `layout` | OCR pages only, optional | e.g. `zweispaltig, senkrecht @48%`, `waagerecht`, `ganz` |

Rules for everyone who generates **or reads** these files:

1. `diagramm` takes precedence: A page whose text is embedded as an image is not a text page — regardless of whether the textlayer could have supplied it.
2. The legacy form `%% S. n %%` or `%% p. n %%` without suffix remains valid and is still read by the review view — it simply lacks the provenance badge.
3. Readers **never guess**: Unknown or malformed suffixes are passed through as layout information rather than interpreted as source provenance.
4. A `%% p. n %%` comment inside a code block is **not** a page boundary.
5. No consumers exist other than the review view: neither `lint_wiki.py` nor `semantic_search.py` touch this folder.

## The Three-Folder Model

Files move between three flat sibling folders — the folder location **is** the status:

```
_ocr-vorschau/              open (awaiting review)
_ocr-vorschau/_akzeptiert/    accepted
_ocr-vorschau/_abgelehnt/     rejected (nothing is ever deleted)
```

`review-status.json` in the same folder is merely an **annotation cache**
(`notiz`, `geprüft-bis`, manual PDF mapping) and can be safely deleted at any time. Details on reconciliation rules: [review-view.md](review-view.md).

`_ocr-vorschau/assets/` remains where it is: All three folders share the diagram images (`![[…png]]`); they are **not** moved alongside.

## Frontmatter Fields

| Field | Meaning |
|---|---|
| `seiten-textlayer` | Lossless from PDF textlayer, exact bold styling |
| `seiten-ocr` | Read via PaddleOCR-VL — **word errors possible** |
| `seiten-diagramm` | Embedded as page image, text inside collapsed callout |
| `woerter-verdaechtig` | Matches from dictionary check, **still in text** |
| `woerter-korrigiert` | Matches replaced during run (only with `--woerterbuch-korrigieren`) |

When `seiten-ocr > 0`, the `Quelle:` link to the original serves as safety net: OCR word errors cannot be mechanically corrected in all cases.

`woerter-verdaechtig` is a work list, not a defect judgment: words remain unchanged in the file, logged during the run with page number and suggestion (`⌕` line), fully viewable with `--woerterbuch-bericht <file>.json`. If both are missing, no dictionary was installed — the run will report this.

## Re-generating

```
pdf2md "raw/ZR/…/file.pdf" --out _ocr-vorschau
```

If a tile derails (repetition loop, exploding count, abort), it is re-calculated with finer slicing. Every such occurrence is listed as a `⚠` line in the run log — even when repair was *not* successful. If you only want detection without re-calculation:

```
pdf2md "raw/…/file.pdf" --out _ocr-vorschau --neuversuche 0
```

Dictionary checking: Enabled by default in reporting mode. Replace clear-cut cases with `--woerterbuch-korrigieren`, disable with `--kein-woerterbuch`. Sources and limits: [scripts-detail.md](scripts-detail.md).

Benchmark metrics and error categories: [../bench/ERGEBNIS.md](../bench/ERGEBNIS.md).

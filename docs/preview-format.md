# Preview Format — Normative Specification

_This is the authoritative description of the `.md` format generated by `pdf2md.py` and parsed by the plugin `vorschau-parser.ts`. Moving forward, both implementations reference this document instead of line numbers in each other's source files._

## 1. Frontmatter

The YAML frontmatter (enclosed by `---`) contains metadata regarding the source PDF and the execution run. Each field is a flat key-value pair.

| Field | Meaning | Format / Allowed Values |
|---|---|---|
| `titel` | Short title (often PDF filename) | String |
| `quelle-pdf` | Path to raw PDF file | String, always JSON-quoted via `json.dumps` |
| `seiten` | Total page count | Positive integer (as string) |
| `seiten-textlayer` | Number of pages with lossless text layer | Integer |
| `seiten-ocr` | Number of pages processed by OCR model | Integer |
| `seiten-diagramm` | Number of pages identified as diagrams | Integer |
| `seiten-entgleist` | Number of derailed tiles (optional) | Integer |
| `woerter-verdaechtig` | Count of dictionary flag matches (optional) | Integer |
| `woerter-korrigiert` | Count of terms replaced (optional) | Integer |
| `ocr-modell` | Model identifier used for OCR pages | String (e.g. `mlx-community/PaddleOCR-VL-1.5-4bit`) |
| `abgebrochen` | Abort notice for partial file (optional, only on orderly abort, Issue #25) | `seite n von m` — `n` = last completed page, `m` = planned total |
| `ocr-datum` | Run calendar date (ISO) | `YYYY-MM-DD` |
| `ocr-zeitpunkt` | Fine-grained ISO timestamp (with time) | `YYYY-MM-DDTHH:MM:SS` |
| `vorschau-format` | Format specification version field | `1` |

### Rules

1. `quelle-pdf` is always quoted via `json.dumps` (even when containing no spaces). The parser reads it as a scalar value — full YAML parsing is intentionally avoided.
2. All fields are optional; missing fields are treated as `undefined` / `null` by the parser.
3. The field `vorschau-format: 1` identifies files created according to this specification. The parser tolerates unknown fields (see Section 7).
4. `abgebrochen` marks a **partial file** resulting from an orderly abort (SIGINT/SIGTERM, exit code 6): the file is incomplete, but intentionally written rather than discarded. Count fields (`seiten`, `seiten-ocr`, …) reflect only pages actually written; `m` in the note indicates planned run total. If the run aborts **before the first page**, no file is generated and pdf2md exits with code 7 — UI must not claim a partial file exists. An abort during the *last* page creates no partial file notice: the file is complete.

## 2. Page Markers

Each page is separated by a comment line that Obsidian renders invisibly. Markers accept optional trailing metadata (`herkunft` and `layout`), maintaining backward compatibility with files generated prior to marker extensions.

```
%% p. {nr} | {herkunft} | {layout} %%
```

| Part | Meaning | Allowed Values / Rules |
|---|---|---|
| `nr` | Page number in PDF, 1-based | Positive integer |
| `herkunft` | Text provenance | `textlayer` \| `ocr` \| `diagramm` |
| `layout` | OCR pages only, optional | e.g. `zweispaltig, senkrecht @48%`, `waagerecht`, `ganz` |

### Rules for Producers and Consumers

1. `diagramm` takes precedence: A page whose text is embedded as an image is not a text page — regardless of whether the textlayer could have supplied it.
2. The legacy form `%% S. n %%` or `%% p. n %%` without suffix remains valid and is still read by the review view — it simply lacks the provenance badge.
3. Readers **never guess**: Unknown or malformed suffixes are passed through as layout information rather than interpreted as source provenance.
4. A `%% p. n %%` comment inside a code block is **not** a page boundary.
5. A format change in `pdf2md.py` without an updated fixture turns CI red (see CI step in `.github/workflows/ci.yml`).

## 3. `Quelle:` Line

Directly following the frontmatter (first line after closing `---`):

```
Quelle: [[raw/ZR/skript.pdf]]
```

- Path is the basename of the PDF file (relative to `raw/` directory).
- The parser extracts this link and uses it as fallback for `quellePdf` if `quelle-pdf` is missing in frontmatter.

## 4. Diagram Callout

Pages marked as diagrams (`herkunft: diagramm`) receive a collapsed callout containing page text.

```
> [!note]- Page text (order not guaranteed)
> Structure of Action for Annulment
> >
> > 1. Admissibility
> > 2. Merits
```

- The title `Page text (order not guaranteed)` (or German equivalent) is fixed.
- Callout text is created from page paragraphs (via `als_callout(absaetze, "Text der Seite (Reihenfolge nicht verlässlich)")`).
- On diagram pages processed with `--diagramm-nur-bild`, the callout is omitted.

## 5. Footnotes per Page

- Footnotes use Obsidian syntax: `[^1]` inline, `[^1]: ...` at block end.
- Footnotes are collected per page (block-level rendering prevents footnote collision across page boundaries).
- Format is generated via `fussnoten_obsidian(absaetze)` in `zusammenbau.py`.

## 6. Code Block Edge Case

A marker `%% p. n %%` or `%% S. n %%` inside code blocks (` ``` ` or `~~~ `) is **not** evaluated as a page boundary. Code block content remains untouched.

```
```
%% S. 99 %%
still page 2
```
```

## 7. Version Field (vorschau-format)

- Field `vorschau-format: 1` in frontmatter specifies compliance with this specification.
- The parser reads this field; if missing or unknown, execution does **not** fail, but evaluates to `undefined`.
- The field is currently **reserved**: written by producer, but not yet evaluated by consumer logic. Future migration checks ("file originated from older format") can leverage this field.
- Existing files lacking this field remain valid (handled as absent).
